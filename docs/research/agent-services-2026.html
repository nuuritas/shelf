Software for agents, not people who happen to have one.

The category got its name this year: SofA. Eight services already sell to it, and five jobs still get handed back to a person on a sofa.

01
The category got named

Y Combinator called it “Software for Agents” in April. In November an essay gave it a usable definition and a name — SofA: software whose primary user is an agent acting for a person, with screens reduced to supervising, approving and paying. A curated index now counts 300 of them across 16 categories, up 111 in 30 days.

02
Money moved first

The most built-out layer is payments: agent wallets, virtual cards, and HTTP 402 machine payments. But the registry is crowded with dead inventory — 96.5% of x402 Bazaar listings show no repeat demand. Real agents paying real money is still a small market, ranked badly.

03
The churn is brutal

17.2% of remote MCP servers are dead and 29.2% grade D or F. Agents discover tools at runtime, so a dead endpoint is not an outage — it is a reasoning failure. This is the biggest unowned problem in the stack.

04
The gap is in the reverse direction

Everyone built the forward path: agents can buy, book, send, browse, and pay. Almost nobody built the undo — returns, revocations, deletions, deprovisioning. That is where the next five businesses are.

Section 01

What counts as SofA

The category has a name and a definition. What it does not have is a test — until a catalogue of 300 services published the rules it rejects entries against.

Y Combinator called it “Software for Agents” on 27 April 2026, and made it a category in its Summer 2026 Requests for Startups. On 12 November, Ozan Caglargil published the essay that compresses it to SofA and defines it: software “whose primary user is an AI agent acting for a person. Everything it does can be done without a screen, and the human interface shrinks to what a person needs to supervise, approve and pay.”2829

Definitions are cheap. The operational version — the part that survives an audit — is in the contribution rules of Awesome Agent-Native Services, a 300-entry catalogue whose maintainers publish the tests they reject entries against. Five of them matter:

1. The vendor names agents as the primary consumer. Not “now with agent support”. The docs address the agent directly. “Email for AI agents” passes. “The developer platform for everything” does not.

2. The API exposes a primitive that only makes sense for an agent. An agent inbox with webhook-on-inbound is a primitive. A standard CRUD API that an agent happens to call is not. This is the test most “agent-ready” products fail: the same endpoint would build a human product unchanged.

3. The agent can complete the loop alone. Sign-up, credential, first successful call, error recovery — without a human reading a dashboard. The catalogue calls the strong version of this URL onboarding: the agent is told to read a machine-readable file and follows it to live credentials.1

4. Identity and policy are per-agent. One credential per agent, scoped, revocable, attributable. Shared keys are the tell that a product was retrofitted.

5. It fails loudly. When the agent is about to do something outside its mandate, the service refuses in a form the model can read and act on — not a 403 with an HTML body.

The line that stuck

“Four out of five is still a miss. A page that says ‘for agents’ can still be a person’s account with a new headline.”

— the index’s own framing of its admission tests 1

Why does this deserve its own category instead of being “SaaS with an API”? Because the economics invert. A human SaaS sells seats and attention; its UI is the product. An agent-consumed service sells calls that complete, and its UI is a machine-readable contract. The buyer never looks at it. The buyer measures it in retries, tokens, and whether the job got done.

Three tells of a retrofit

  • One API key per customer. Every agent in the fleet shares the same credential, so nothing is attributable.
  • Onboarding needs a browser. If a human must accept terms, pick a plan, or copy a key, the agent cannot onboard itself.
  • The error path is a dashboard. Failures surface as a chart someone checks on Monday, not as a typed error the agent can branch on.

What “agent-native” is not

  • An MCP server bolted onto a REST API with 400 endpoints.
  • A chat UI over a product built for humans.
  • “Works with Claude” in a footer.

x402 listings with repeat demand

Two readings of that distribution are possible, and the evidence supports both.

The generous reading: infrastructure gets built before applications, exactly as it did for the web. Sandboxes, memory, browsers and payment rails are the picks and shovels; the 22 commerce services and 9 voice services are the beginning of the demand side.

The unkind reading: the cluster is where the LLM labs shipped a primitive and a hundred wrappers followed. Context compression, code sandboxes and browser orchestration are all things a competent agent runtime can own — and increasingly does.

The number that settles it is not the category count. It is 17.2%. If roughly one in six advertised tool endpoints is dead, then the discovery layer is the product, and everything downstream is priced on reliability. A service that answers every time is worth more than three that answer usually.

Where the money is actually moving

  • x402 Bazaar: 14,865 listings, 1,561 hosts, ~260,000 calls in 30 days. Top 10 sellers take 89% of organic volume.6
  • MCP registry: 18,849 servers, 18,650 active, 9,326 with a remote endpoint. Half cannot be used without pulling code locally.5
  • Median price per call: $0.014. Whole-registry organic GMV: roughly $3,000–6,000/month.6
  • Attrition: at least one well-reviewed 2026 launch, tilde.run, has already shut down.22

Eight that work today

Not “promising”. Live, with a documented way for an agent to start using them without a human in the loop, and evidence they are being used. Star counts and creation dates read on 13 Nov 2026.

Your agent gets spending credentials from your Link wallet — a virtual card number, a Link Pay Token, or a Shared Payment Token — and you approve every purchase. The real card details are never exposed to the agent, and the card works anywhere, not just at Stripe sellers.

AgentMail

A mailbox per agent. Send, receive, thread, and search mail; inbound messages fire a webhook so the agent can act on them. Built for the unglamorous half of autonomy: receiving a verification code, answering a vendor, keeping a paper trail.

Three patterns recur across all eight.

The primitive is smaller than the product used to be. An inbox, a spending credential, a browser session, a compression pass. Each is a thing an agent does mid-task, then discards. The value is in being callable, not in being a destination.

Onboarding is machine-readable or it does not count. Half of these can be joined by an agent with a single instruction: read this file, call this endpoint, you are live. That is a new distribution channel, and the reason a 300-entry catalogue can exist at all.

The trust layer is consortium-shaped. Payment rails, identity registries and adjudication are being standardised by groups — FIDO, the Internet Court consortium, ERC-8004 — rather than won by a single vendor. That is the signature of a layer that is becoming infrastructure.

Also moving, worth watching

  • Moltbook — a social network built only for agents, humans read-only. Proof that “agent internet” is becoming literal.16
  • Mireye (YC S26) — infrastructure for physical-world agents. Announced Sep 2026; the frontier of “service” meaning someone drives a van.15
  • Agent identity — mTLS proxies, signed identity pages, KYA tokens. All issuance, no revocation.1213
  • Plannotator — an email-like inbox for reviewing and annotating agent work. Oversight as a product surface.17
Section 04

The rails underneath

Seven standards now cover what an agent needs to find a service, pay it, prove authority, and complain. None of them covers what happens after a job goes wrong.

The convergence is visible from here. Within one stack an agent can now: be discovered through a registry, onboard itself from a skill file, prove delegated authority, pay per call, and get an authorisation receipt that a third party can check. That is a complete happy path.

The unhappy path is still manual. Refunds, returns, chargebacks, contract breaches, revocations and data deletion all route back to a human at a support desk, and each one is a place where a service could stand between the agent and the mess.

Section 05

The SofA frame

Two documents named the category this year. Between them they supply the definition, a product checklist, and an honest counter-argument.

Y Combinator, 27 April 2026. The post is four sentences, but the video version is where the specification lives: agents are already “browsing the web, doing research, making purchases, and managing legacy CRMs” — on top of software “designed for humans clicking buttons”, which makes them “slow, inconsistent, and brittle”. What agents need instead is machine-readable interfaces — APIs, MCPs, CLIs — and documentation thorough enough to “discover, sign up for, and instantly start using new tools programmatically without needing a human in the loop.” The conclusion is the thesis of this note: while everyone builds agents, “the biggest opportunity might be building the software that those agents depend on.”28

Ozan Caglargil, 12 November 2026. The essay does the thing YC did not: it gives the category a name, a boundary, and a table you can argue with. The definition is the load-bearing part.

Definition

SofA is software whose primary user is an AI agent acting for a person. Everything it does can be done without a screen, and the human interface shrinks to what a person needs to supervise, approve and pay.

— SofA, Software for Agents, 12 Nov 2026 29

The shift the essay describes, paraphrased

The product checklist. Six lines from the essay are the most useful test I found for whether something is really SofA: every button is also a call; the documentation is the onboarding; errors give directions; permission is borrowed and limited; the price fits a customer that never sleeps; and there is a view from the sofa. The catalogue’s five admission tests in section 01 are the same idea, audited from the outside.29

Where the engineering lands. A checklist describes behaviour; it does not describe how to be callable twice. The composition literature supplies that half: skills and tools as typed operations with declared inputs, outputs and failure modes, composed rather than prompted. SkillComposer (July 2026) formalises it for agent skills; the semantic-algos pack applies the same shape to reasoning — each operation runs in a fresh subagent and hands the next a file.2425 Practically, the three properties that make a SofA product composable are a contract, a stable effect, and an inspectable trace.

The bear case, in numbers

  • Forrester, 11 Feb 2026: “over $1 trillion in market capitalization was erased from software stocks” in seven days. The post’s title was “SaaS As We Know It Is Dead”.
  • Gartner, via CIO.com 2 Jul 2026: up to $234 billion of application software spend at risk by 2030 — about 20%. Four fifths stays.
  • IDC: “by 2028, pure seat-based pricing will be obsolete”; December 2025 verdict, “SaaS is not dead, but it is metamorphosing”.
  • Box’s Aaron Levie, 28 May 2026: the seat model will be “quite durable”, and agents arrive “primarily through the API”, on a consumption model.
  • Panic half-life: US searches for “saas is dead” peaked at 2,900/month in May 2026, 260 by August.

All five figures as reported and dated in the SofA essay.29

Section 06

Five that do not exist yet

Each one is a job an agent can already attempt, cannot safely finish, and cannot finish alone. Confidence is my read of the evidence, not a market forecast.

Gap 01
Contract drift

The change feed for agent tools

Registries tell you a tool exists. Nobody tells you it changed. Schemas shift, auth flows tighten, a field quietly becomes required, a response shape gains a wrapper — and the agent finds out at runtime, mid-task, as a failure it will misdiagnose as its own mistake.

Nearest thing
Registry audits that measure reachability: 17.2% of remote endpoints dead, 29.2% graded D or F. They count corpses, not changes.5
Why an agent can’t do it
It would need to watch thousands of endpoints from outside, on a schedule, and sign what changed. An agent only ever sees its own failures.
Smallest shippable
A per-endpoint feed: nightly schema diff plus three behaviour probes, severity-classed as breaking or not, delivered as an MCP tool and a webhook.
Confidence
High
Gap 02
Revocation

Deprovisioning, or the agent death certificate

The ecosystem has become extremely good at issuing identity to agents: mTLS proxies, signed identity pages, KYA tokens, per-agent wallets, inboxes, browser profiles. There is no counterpart product for taking it all back. Retire an agent, or discover one is compromised, and you are left revoking credentials by hand across twenty dashboards.

Nearest thing
Issuance, everywhere: mTLS identity proxies, agent accountability registries, AP2’s authorisation log. Nothing that revokes across vendors.1213
Why an agent can’t do it
Revocation is per-vendor semantics, and it needs custody of the grants. The legal question — can an agent sign away another agent’s authority? — has no clean answer.
Smallest shippable
One command that revokes N credentials, kills live sessions, rotates webhooks and returns a signed receipt. Start with the ten services fleets actually use.
Confidence
High
Gap 03
Undo

Reverse commerce as a service

Buying is solved: wallets, virtual cards, per-call payment, agent checkout. Unbuying is not. A return needs an RMA, a carrier label, a drop-off, a refund that lands weeks later and a dispute if it does not. No agent session lasts that long, and merchant support desks are built for humans holding a phone.

Nearest thing
The buy side, densely: 22 commerce services, Link’s three credential types, x402 and MPP rails. The reverse path is a support ticket.93
Why an agent can’t do it
The work outlives the session, the APIs are inconsistent or missing, and the money movement needs an entity willing to be liable for a wrong refund.
Smallest shippable
A durable return run: RMA request, label, courier booking, refund tracking, escalation — for five large merchants, exposed as a skill that can live for thirty days.
Confidence
Medium
Gap 04
Forgetting

Deletion with proof, for agent memory

Memory is consolidating into formats and standards — file-based stores, universal protocols, a push for an OpenTelemetry-style memory format.14 Compliance has not followed. A memory of a customer is copied into a vector index, a filesystem, a trace, a cache and a prompt history. “Delete it” is currently an assertion, not evidence.

Nearest thing
Memory infrastructure and format proposals. The regulated question — show me it is gone, and when — has no product.
Why an agent can’t do it
Proving absence across systems you do not own requires an auditor’s authority, and the legal definition of “deleted” differs by jurisdiction.
Smallest shippable
A deletion receipt for one memory store: enumerate copies, delete, re-index, prove absence, export a signed certificate with timestamps.
Confidence
Medium
Gap 05
Procurement

Agent as a buyer of software

Agents can now join services from a URL. They cannot yet procure one: compare plans, accept terms, choose a billing entity, add seats, calendar the renewal, cancel before it rolls over. Payments are covered — Link handles recurring credentials — but the commercial decision around the payment is still a human clicking “I agree”.

Nearest thing
URL onboarding for tools; recurring payment credentials. Neither touches terms, seats or renewal.1
Why an agent can’t do it
Terms of service are prose, not a schema; billing identity is a legal entity; and vendors actively do not want autonomous signups.
Smallest shippable
A procurement agent with hard policy limits that diffs terms, picks a plan, executes the purchase and files the renewal date — against a vendor whitelist.
Confidence
Low
If I had to pick one

The contract-drift feed. Every other layer assumes the tools keep working; 17.2% of them already do not. A service that turns silent breakage into a typed event would be cheap to build, miserable to maintain, and would make every agent above it measurably better — which is the shape of a good infrastructure business.

Section 07

Method and caveats

What was checked, what was taken on trust, and what I could not verify.

Reading the request. The first draft read “sofa” as a garbled SaaS. It is not: it is SofA, the name from the essay you saved as kvxb9. The archive settled it, and the rest of this note follows the archive.

How the examples were chosen. Only services that are live, name agents as the caller, expose an agent-specific primitive, and have a documented self-onboarding path. Star counts and creation dates come from the GitHub API on 13 Nov 2026; launch dates come from Hacker News items. Stars measure attention, not revenue — a 79,000-star repository and a profitable company are different claims.

The two registry audits are third-party. MCP Queen probes every remote server on a cycle and publishes its dataset; the x402 Bazaar survey reads Coinbase’s public discovery endpoint. Their numbers are reproducible from those endpoints, but I did not re-run either census myself. Treat them as strong evidence of direction, not audited fact.

On the two documents. You remembered the reference as “why combinators” — voice-to-text for Y Combinator’s. It is the post of 27 April 2026 (shelf ref 67bsh), and the overall document is the SofA essay (shelf ref kvxb9, saved 13 November). Both were read from your Shelf archive, including the video transcript, then checked against the live pages.

What is deliberately missing. No funding rounds, no valuations, no market-size projection. They date badly and none of them tell you whether an agent can complete a loop.
